## Scope and API
POST /api/v1/notifications/auction-cancellations,Service/Admin trusted Gateway,200 pure AuctionCancellationResponse,16KiB/no-store. Source Auction commits cancellation/authorization/bid-count rules and supplies affected recipients;Notification does not cancel bids/orders,release inventory,refund money or change reputation. First cancellation substep only;payment-timeout and Seller winner-result still pending. REST only.

Bounded fanout:one recipient per POST,same immutable source event/header for all recipients;source enumerates verified impacted users and retries only failed user with same event/recipient. No unlimited recipient array or guessed users from Notification device table. Header event PK+unique auction dedups cancellation aliases;recipient unique(event,user),one logical item with InApp+per-device Push. One user's failure never rolls back already accepted recipients. Source owns complete list,concurrency/backpressure and end-to-end completion;server response only acknowledges this recipient,not whole audience.

GET /api/v1/notifications/auction-cancellations/{notificationId},authenticated owner,200 InAppNotificationItemResponse;anonymous401,foreign/deleted/non-cancellation404. Push-only detail allowed,GET no read change. Client resolves auctionId and rechecks Auction permissions/state,no arbitrary redirect/URL.

## Strict request and source rules
Required nonempty sourceEventId,auctionId,sellerUserId,recipientUserId;AuctionTitle<=200 nonblank;Reason<=500 user-safe nonblank (bounded for FCM size);CancelledAt UTC<=now+30sec,historical allowed;BidCount required int>=0. CancellationKind Seller/Admin,RecipientKind Seller/Participant case-insensitive text names only. Seller cancellation requires BidCount=0 and Seller recipient;Seller kind recipient==SellerUserId,Participant recipient!=SellerUserId and BidCount>0. Declared-shape checks do not prove actual authorization/participation:source must verify Admin forced-cancel/Seller no-bid rule and correct targets before sending. Optional trace<=100;no controls in text. Unknown JSON rejects recipient arrays/private bank/documents/password/token/URLs/data/template fields. Reason must exclude sensitive internal evidence;plain text client rendering required,not automatic PII redaction.

Header canonical hash auction,seller,title trimmed,reason trimmed,cancellationKind lower,bidCount,cancelledAt UTC microseconds;trace/recipient excluded so all recipients must share identical original source header. Same event with changed header409 AUCTION_CANCELLATION_CONFLICT;different event same auction409 AUCTION_CANCELLATION_ALREADY_NOTIFIED. Same event+recipient replay current state,no extra delivery/audit;new verified recipient accepts independently. Source cannot silently correct cancellation metadata or change recipient kind for same user. Reserved keys persist across soft-delete. Source resubmission/recreated auction has new auction ID.
