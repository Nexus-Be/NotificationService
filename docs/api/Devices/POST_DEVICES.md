## Ownership and concurrency
New token creates one row. Same owner refresh preserves ID/CreatedAt, sets active and advances lastSeenAt/updatedAt at PostgreSQL microsecond precision, strictly later than old updatedAt. Active token owned by another user409 DEVICE_TOKEN_OWNERSHIP_CONFLICT. Explicit logout revoke by prior owner releases inactive token for later account transfer; audit captures old/new owner IDs and platform. Soft-deleted token409 DEVICE_TOKEN_UNAVAILABLE, never resurrected. previousToken missing/foreign/deleted404 DEVICE_TOKEN_NOT_FOUND without distinguishing cases. An alreadyinactive owned previous token can be rotated again safely. Supplied same new/old token400.
PostgreSQL transaction takes sorted advisory locks by SHA256 token fingerprint (seed8008) and row locks. Existing unique Token index covers all rows. New token mutation, old-token revoke and audit SaveChanges commit atomically; external unique race409 DEVICE_TOKEN_CONFLICT rolls back whole mutation including previous revoke. Revoke uses same protocol and fresh owner state; old owner cannot later deactivate a reassigned row. Multiple same-user refresh requests produce one device but one heartbeat audit per accepted POST; POST not idempotency-key replay. In-memory test provider uses tracked mutations without SQL locks; production uses PostgreSQL.

## Audit/privacy and FCM
DeviceRegister5 records create/refresh/reactivate/transfer/rotate; DeviceRevoke6 only if previous/revoked token was active. Audit fields contain deviceID, actor/owner GUIDs, platform/active/time and SHA256 fingerprint, never raw token, OTP or request body. Response keeps raw token for existing client compatibility; API routes/tokens must be treated as sensitive operational data. Provider callback invalidation already requires matching ID/owner/token/updatedAt; monotonic refresh stamp prevents an old UNREGISTERED response from disabling the refreshed registration. Existing in-flight sends cannot be recalled by registration changes. Rotation leaves old device reference inactive, so old pending deliveries skip instead of targeting new device accidentally.
